Review of [PR #70](https://github.com/niklucky/testron/pull/70), originally at `09cc135`, and implementation of [issue #35](https://github.com/niklucky/testron/issues/35).

The source-authority design is viable, but the original implementation had several correctness gaps that would have made browser synchronization unreliable. The following findings were fixed in this working tree.

| Priority | Finding                                                                                                                                                                                                                                          | Resolution                                                                                                                                                                      |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P1       | The parser could turn computed/optional calls, custom URL predicates, and locator options into structured actions with different behavior. Some syntactically valid values also failed the step schema later and broke snapshots.                | A projection must pass the step schema and match the generated statement's syntax tree. Unsupported semantics remain exact code.                                                |
| P1       | Invalid source retained offsets from the last successful parse. Deleting or editing a displayed step could splice unrelated characters in the new draft.                                                                                         | Invalid drafts retain their displayed steps but discard editable ranges. Appending and structured mutations cannot overwrite invalid source.                                    |
| P1       | Recording an assertion or variable fill appended only the statement, omitting `expect` or `requiredEnv`. Compact formatting could cause the recorder to regenerate the entire document; a final unrelated callback could receive the new action. | Insertion uses the parsed test callback's boundary and adds required dependencies. Existing file-level code and comments survive.                                               |
| P1       | An invalid source draft could still run its older persisted steps. File-level hooks, alternate fixtures, and additional test declarations could be silently skipped.                                                                             | Desktop and server runners validate source before browser launch and derive their execution steps from it. Unsupported complete-spec behavior is rejected before actions begin. |
| P1       | Editor drafts and delayed saves were not scoped to a test. Switching tests while a write was pending could overwrite the newly selected test.                                                                                                    | Shared draft state scopes acknowledgements and writes to a document ID and flushes pending changes to that document when leaving it.                                            |
| P2       | Valid local source edits persisted without publishing the acknowledgement expected by the editor. Empty drafts were replaced with generated source on reload.                                                                                    | Edits publish snapshots; explicitly empty documents stay empty. Legacy documents without source are generated at the loading boundary.                                          |
| P2       | Re-parsing newly captured actions discarded alternatives, warnings, timestamps, and some secret bindings. Positional matching could steal another step's metadata.                                                                               | Matching reserves unchanged actions first. Undo/redo retains recorder metadata alongside source, with bounded history.                                                          |
| P2       | The separate native code-panel renderer still used the old read-only panel and forwarded code selection as step selection.                                                                                                                       | It now hosts the source editor and sends source-edit events independently of step-selection events.                                                                             |
| P2       | Routine recording-context updates could rename edited source back to an older library title and create extra revisions. Local repository renames did not update source.                                                                          | Context application does not rename the document; explicit renames update its title.                                                                                            |

Clicking a manual step now synchronizes the embedded tested browser with the state **after** that step. Forward movement executes the remaining unchanged prefix. Backward movement, deletion, edits to an applied prefix, or an invalidated browser position reset browser storage, reapply the selected authentication profile, load the starting page, and replay through the requested step. Selecting a target step also highlights its element when it is present and visible.

Replay pauses recording, rejects unsupported source before side effects, serializes browser effects, cancels superseded requests, and reports the last completed step on failure. Trusted user interactions with a paused page invalidate its cached position. Resuming recording after step navigation first returns the browser to the end of the current steps. Source editing and code cursor movement do not move the browser.

Integration testing found and fixed two additional issues: observed navigation URLs were being fed back into the webview's `src`, causing competing loads, and keyboard replay needed to focus the tested WebContents so Enter would not activate the recorder's selected row.

Validation covers parser and session regressions; replay ordering, invalidation, cancellation, failure, and deletion; desktop/server execution; and an Electron test using the real source editor and tested page. The Electron scenario checks fills, backward clearing, forward navigation, deletion, rapid selection, click/Enter form submission, hover, checks, and assertions. TypeScript checks, production webapp/Electron builds, and ESLint were also run. Repository-wide lint excludes the unrelated nested `.claude` worktree, whose independent ESLint configuration otherwise conflicts with this checkout.

Browser reset does not roll back changes made on a remote server. Tests that change server state still need repeatable fixtures or application-level reset behavior. Exact code, custom setup/fixtures, and multiple tests require a future complete-spec runner. Replay supports the structured main-frame action model; the native locator resolver is not a complete replacement for Playwright's accessibility and selector engines. Arbitrary scripts, iframe traversal, and popup replay are outside that model.

Recorder reopening regression: Electron can treat reopening the same renderer URL as an in-page navigation, leaving React's webview element mounted after its guest was closed. Recorder openings now use a fresh document, and step replay recreates a missing guest and waits for attachment before resetting or executing actions. Guest destruction also invalidates the applied prefix. The Electron regression reproduces the original failure and verifies both reopening and recovery after guest destruction; both replay integration tests pass, alongside 16 replay/session unit tests and desktop type checking.

Saved browser-state authentication: the recorder previously wrote local storage into the current page after navigation. That was too late for startup authentication checks, and replay resets were applying origin-specific storage while the page was `about:blank`. The preload now restores only its own origin's saved local storage synchronously before application scripts execute. Cookies are restored before navigation; browser clearing and profile updates share a serialized queue. The saved profile is seeded once per origin after each reset, so later actions such as logout remain effective. Resetting first unloads the old document and waits for the blank page's load event, including Electron's case where that event fires but the navigation promise never resolves. The authenticated Electron regression covers initial page startup, backward/forward selection, logout, and reopening the saved test in a fresh process.
