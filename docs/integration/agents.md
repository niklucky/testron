# Testron agent workflow

Use the maintained skill at https://testron.dev/agents/SKILL.md. It is also bundled
with the CLI: `testron docs --skill`. `testron init --agent` writes a local copy to
.testron/SKILL.md and links the agent guide from AGENTS.md.

1. Read testron.config.ts and run testron pull for current suite references and IDs.
2. Choose portable (`ci-and-testron`) or catalogue (`ci-only`) execution. Publication
   is independently opt-in. Keep complex repository setup intact for CI tests.
3. Write the test's human-readable title, description, and expected scenario steps.
   Review portable tests against the operations generated by the Testron editor.
4. Run locally with the repository's tooling and explicitly configured local target
   and authentication. Never fall back to a production URL or remote profile secrets.
5. Within the user's publishing scope, inspect push --dry-run and then push. Preserve
   IDs. Report catalogue downgrades, conflicts, unsupported runtime behavior, and
   reporting failures accurately.
6. Configure the Playwright reporter when QA needs local/CI results. Reports and source
   synchronization are separate operations. Neither enables CI-only remote execution.

Agent review replaces a new authoring-validation gate. The skill does not authorize
Git pushes, external messages, or deployment beyond the user's request.

## Set up CI result reporting

Use the [Playwright reporting guide](https://testron.dev/docs/playwright) for the
full developer setup and GitLab example. When configuring a repository:

1. Make `@testron/cli` available in the CI job. Before a package release, use the
   built archive through a location accessible to CI, not a laptop-only path.
2. Add `['@testron/cli/reporter']` alongside the existing Playwright reporters.
   Preserve the project's test command, prepared environment, and artifact handling;
   check for command-line `--reporter` overrides.
3. Point `server` in `testron.config.ts` at a reachable Testron instance. Localhost
   in CI refers to the runner. Configure a project API key as the masked secret
   `TESTRON_API_KEY` and set `TESTRON_REPORT_ENVIRONMENT_ID` to a CI environment UUID
   in that project (or use config `reportEnvironmentId`). Do not print credentials.
4. Keep stable test IDs, repositoryId, and suite references committed. For a fresh
   checkout, run `testron pull --tests --suite <codeKey>` for each suite being reported
   before the normal test command. `testron pull --test <uuid>` selects one test.
   Plain catalog pull does not establish the reporter's revision baseline. A push
   establishes it only in the checkout where that push runs.
5. Resolve source conflicts against the intended commit; do not overwrite local work
   or automatically publish changes to bypass a conflict. Result-reporting setup is
   separate from authorization to publish test definitions.
6. Run the repository's normal Playwright command. The reporter uploads completed
   attempts automatically, reporting only tests annotated with `testron.id`. Check
   reporter errors and the resulting Runs entries before claiming upload success.

`CI=true` labels reports CI; otherwise they are repository-local. Reporting
does not change the execution target or make CI-only tests runnable on Testron.
Results include status, duration, errors, revision, source hash, Playwright project,
and retry. Reporting errors fail the run; skipped/interrupted tests currently map
to cancelled. Screenshots, videos, and traces stay in CI artifacts for now.
